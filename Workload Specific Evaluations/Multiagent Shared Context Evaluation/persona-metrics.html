How to read it
  • Pairwise cosine similarity of agent outputs (0–1). Green = aligned, red = divergent.
  • Diagonal is always 1.0 (self). Read the off-diagonal cells.
  • Very high everywhere can mean redundancy (agents echoing); very low can mean drift or disagreement.
Alignment is a proxy, not a verdict: agents can be highly aligned and consistently wrong. Confirm with Groundedness.

Three cautions

Partitioning metrics by persona speeds up triage — but taken literally it misleads. Keep these in mind.
1

Failures hide in the seams between personas

Engineer: Write Accuracy 5/5Output is consistent with its input → looks healthy.
PM: Groundedness 2/5Output doesn't match reality — the input premise was wrong → broken.
Personas are lenses, not owners. Same agent, same turn, opposite verdicts. If each persona reads only their column, nobody owns the seam — and the seam is where the failure lives. Give everyone a home dashboard, but gate releases on a cross-persona read.
2

The same metric means different things

Coordination Token %SRE reads it as cost. Engineer reads it as context bloat / prompt quality.
LatencyOps reads it as an SLA. PM reads it as user-perceived responsiveness.
A persona view = metric + interpretation + threshold, not just a filtered column list. The metric is shared; the meaning and the alert threshold are not. Don't assume a shared definition just because you share a column header.
3

Persona is a different axis from lifecycle stage

WHO (persona)PM / Domain • App Engineer • Platform • SRE
WHEN (stage)Design • Code • Deploy • Operate
Keep two axes: who + when. They correlate but aren't identical. Groundedness isn't “design-only” — it's a design-time gate AND a production canary (e.g. drift after a model swap). Collapsing the axes makes coverage look complete when it isn't.
